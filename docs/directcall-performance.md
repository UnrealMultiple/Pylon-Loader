# IL2CPP 直调优化实测与 Bunny 对比

> 测试日期：2026 年 11 月 11 日。单位除特别说明外均为纳秒/次，越低越好。
>
> **结论：静态布局证书在同机交替暖循环中，相对线程局部缓存路径取得约 1.30～1.35 倍加速；当前标准跨帧测试尚未证明性能改善，也不能宣称超过 Bunny。**

## 一、测试范围与版本

本轮优化覆盖三个生成代理试点，不代表所有游戏方法均已采用相同快路径：

- `MathHelper.Clamp(float,float,float)`：三个单精度参数、单精度返回。
- `Vector2.Distance(Vector2,Vector2)`：两个浮点同质聚合参数、单精度返回。
- `Matrix.Add(Matrix,Matrix)`：两个 64 字节结构体参数、调用方间接返回缓冲。

## 二、优化内容与安全边界

调用链由通用参数打包逐步收敛为：

```text
生成代理直接填帧
    → 读取静态布局证书
    → 校验方法标识和布局形状
    → 读取当前方法指针
    → 原生线程校验与异常保护边界
    → 执行真实 IL2CPP 方法
    → 读取返回值或调用方返回缓冲
```

主要变化：

1. 三个试点直接填写调用帧，绕过参数指针数组和动态参数打包器。
2. 将认证后的布局证书保存到生成代理的私有静态字段，缓存命中时不再查询线程局部方法哈希缓存。
3. 证书由运行时依据元数据生成，方法或形状不匹配时重新认证；不支持的布局返回兼容调用路径。
4. 正式构建从缓存帧入口编译移除两个诊断开关读取和线程局部缓存对照分支。入口中间语言体积由 243 字节降到 162 字节，**这不是机器码大小，也不能据此直接推算提速比例**。
5. 显式诊断构建才保留交替选路；正式版拒绝不可用的对照请求，不会把同一路径测两次后伪称对照。

保留的安全措施：

- 保留原生自定义异常保护边界，不全局启用 `SuppressGCTransition`。
- 保留游戏线程调用限制，不允许工作线程绕过检查。
- 保留整个 `PylonCallFrame` 的零初始化，不能只初始化已用参数槽。
- 不扫描机器码，不跳过方法指针包装，不直跳内部调用目标。
- **不缓存目标函数地址**，每次调用仍从方法元数据读取当前方法指针。
- 保留间接返回缓冲检查、布局认证、旧 `Invoke` 和 `TryInvokeFrame` 兼容入口。
- 不以托管重实现替代真实游戏方法调用。

布局缓存与既有方法计划字典均假设方法元数据在进程内稳定；若未来引入域重载或元数据地址复用，必须同时设计两类缓存的失效机制。

## 三、同机交替对照：静态证书的实际收益

### 测量条件

- 时间：19:56:52 开始。
- 同一台手机、同一游戏进程、同一批生成代理。
- 三组，每组五对交替测量；每对交换两侧顺序。
- 每侧每次测量 20,000 次真实调用，测量前先完整预热同一个强类型循环。
- 数值包含循环开销，不扣空循环。
- 为隔离已复现的渲染纹理断言，诊断期间暂时隐藏覆盖层，结束后恢复。
- 两侧调用深度一致；不使用早期多了一层包装的诊断版本计算最终收益。

### 各组中位数完整保留

| 方法 | 线程局部缓存：三组中位数 | 静态证书：三组中位数 | 各组中位数再取中位数 | 吞吐加速比 |
|---|---|---|---|---:|
| Clamp | 112.61 / 86.67 / 86.57 | 83.82 / 64.40 / 64.37 | 86.67 → 64.40 | 1.346 倍 |
| Distance | 89.94 / 89.85 / 89.77 | 67.83 / 67.55 / 67.35 | 89.85 → 67.55 | 1.330 倍 |
| Matrix.Add | 97.16 / 96.90 / 97.21 | 74.88 / 74.65 / 74.59 | 97.16 → 74.65 | 1.302 倍 |

所有数值正确性检查通过。这里比较的是**新生成帧入口的两种计划获取方式**，不是未修改旧代理与新代理的完整对比。运行时编译后的代码形态也可能贡献差异，不能把全部差值机械归为哈希查找成本。

**本表不是标准 Bunny 成绩，也不是正式版删除诊断分支之后的新增提速证据。**

### 为什么不能用持续暖循环宣布超过 Bunny

| 方法 | Pylon 持续暖循环：静态证书 | Bunny 历史参考 | 能否据此宣布超过？ |
|---|---:|---:|---|
| Clamp | 64.40 | 74 | 不能 |
| Distance | 67.55 | 106 | 不能 |

这些 Pylon 暖循环数值确实更低，但覆盖层状态、预热方式、循环结构、执行调度和手机均不相同。它们只说明特定热状态下的性能潜力，不是同条件胜负。

本轮未核实 Bunny 是否使用特定垃圾回收转换策略或异常保护实现，**不推测它通过省略保护取得成绩**。

## 六、为何暖循环与标准测试差距很大

已确认和未确认的因素分开记录：

| 因素 | 当前证据 | 可以得出的结论 |
|---|---|---|
| 循环结构 | 原对照循环反复覆盖结果；标准循环累加结果，Clamp 输入随循环变化 | 两套计时不完全等价 |
| 预热与调度 | 完整 20,000 次预热后立即测量，对比仅 16 次预热后跨帧测量 | 不能将两个数字直接互换 |
| 处理器频率与迁核 | 实测核迁移和 883,200 → 2,438,400 千赫频率端点变化；一次 Clamp 首段 466.51、热段 168.09 | 频率状态确实变化，但端点不能代表整个测量区间 |
| 跨帧本身 | 同核同频端点的标准 Clamp 循环，首段/热段中位数 119.49/118.62；Distance 为 98.88/96.55 | 跨帧不是固定翻倍的附加成本 |
| 反向波动 | 频率不同的部分跨帧样本中，静态缓存反而较慢 | 必须保留全部样本，不能只展示最快情况 |
| 即时编译分层与动态优化 | 未采集编译分层或优化事件 | 尚不能确定是主要原因 |
| 调度抢占、缓存、热状态 | 尚无完整跟踪 | 尚不能分别量化 |
| 空循环扣除 | 本轮空循环远小于多数差值 | 不能用扣除空循环解释全部差异 |
