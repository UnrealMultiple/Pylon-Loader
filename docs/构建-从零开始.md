# 从零构建（新 clone 的完整步骤）

这份文档解决的问题：仓库里**故意不含**三类二进制，新 clone 直接编译会缺件。按顺序补齐即可。

先跑自检，它会把缺什么、用什么命令补，逐条列出来：

```powershell
pwsh -File src/csharp/tools/check-env.ps1
```

## 0. 仓库里有什么、没有什么

| 内容 | 进 git | 为什么 |
|---|---|---|
| `src/app/ src/game/ src/common/ src/core/ src/csharp/managed/ src/csharp/samples/ src/csharp/tools/ src/csharp/il2cppinterop/` 源码 | ✅ | 项目本体 |
| `gradle/` wrapper、`*.gradle.kts`、`docs/` | ✅ | 构建工程与文档 |
| `refs/` 的游戏文件（dump） | ❌ | 游戏文件有版权，**只能从你自己买的 APK 解**，且永不随产物分发；只有说明文档 `refs/README.md` 进 git |
| `runtime/`（CoreCLR + BCL + BepInEx 托管栈） | ❌ | 上游发行包，上百 MB；按下面第 3 步取 |
| `interop/generated/`（Il2CppInterop 代理程序集） | ❌ | 由游戏程序集派生，属于游戏代码的衍生物，不能分发 |
| `src/app/src/debug/assets/`、`src/app/src/main/jniLibs/`、`src/app/src/debug/assets/pylon-interop/` | ❌ | 由上面三项 + 编译产物生成 |
| `local.properties`、`debug.keystore` | ❌ | 本机路径与调试签名材料 |

## 0.5 外部依赖（子模块：只钉源码，不含产物）

```bash
git clone --recurse-submodules https://github.com/Controllerdestiny/Pylon-Loader.git
# 已经 clone 过：
git submodule update --init --recursive
```

| 子模块 | 钉的提交 | 作用 |
|---|---|---|
| 仓库内 [`src/csharp/il2cppinterop`](../src/csharp/il2cppinterop/) | `81a6f78` | Il2CppInterop 的 `Runtime`/`Generator`/`CLI`/`HarmonySupport` 源码（已打 ARM64/Disarm 补丁）。生成 `interop/generated/` 的生成器在这里 |
| [`external/BepInEx-Android`](../.gitmodules) | `625d8b1` | 产出 `runtime/` 的构建系统：`provenance/` 里锁定了 .NET 运行时、MonoMod、Il2CppInterop 的版本，`scripts/` 里有抓取/打补丁/打包流程 |

**子模块只提供源码，不提供产物。** 那些 `libcoreclr.so`、`dotnet.zip`、`BepInEx.Android.zip`
仍然要按下面的步骤构建或从上游 release 取 —— 它们体积大、且必须与游戏同构建，不进仓库。

> 钉提交而不是追分支的原因：`Il2CppInterop.Runtime` 的版本必须与 `interop/generated/` 和
> `src/csharp/il2cppinterop` 完全对齐，漂一个提交就会出现"解析得到类型、调用就对不上"的问题。

### 产物来源链（三类产物分别是谁做出来的）

| 产物 | 原始来源 | 谁产出 | 在本项目落到哪 |
|---|---|---|---|
| `dotnet.zip` | 微软 NuGet 包 **`microsoft.netcore.app.runtime.android-arm64` 10.0.12**（版本与 SHA-256 钉在 `external/BepInEx-Android/provenance/dotnet-runtime.env`） | `external/BepInEx-Android/scripts/fetch_dotnet_runtime.sh`：解 nupkg，取 `runtimes/android-arm64/lib/net10.0/*.dll`（BCL）与 PAL `.so`，用 `zip_deterministic.py` 打成 zip | 随上游 release APK 的 `assets/` → `extract-bepinex-android.ps1` → `runtime/bepinex-android/assets/dotnet.zip` → `prepare-runtime.ps1` 摊成 `dotnet/` |
| `BepInEx.Android.zip` | 上游 BepInEx `5b766a3b`（`v6.0.0-pre.2-74`）+ 13 个补丁；Il2CppInterop `81a6f78` + `references/il2cppinterop-arm64-disarm.patch`；MonoMod 补丁版（`provenance/monomod.env`） | `external/BepInEx-Android/scripts/package_bepinex_android.sh`（依赖 `build_il2cppinterop.sh`、`build_monomod.sh`、`build_native_deps.sh`） | 同上 → `runtime/bepinex-android/bepinex/` |
| `interop/generated/` | **你自己的游戏文件**：`refs/lib/arm64-v8a/libil2cpp.so` + `global-metadata.dat` → Il2CppDumper 的 `DummyDll/` | `Il2CppInterop.CLI generate`（源码在 `src/csharp/il2cppinterop`）；命令见第 4 节 | 直接放 `interop/generated/`，`deploy-runtime.ps1` 再拷进 `src/app/src/debug/assets/pylon-interop/` |

两个 `.db` 是判断凭据：`MethodAddressToToken.db`、`MethodXrefScanCache.db` 只在走
`Il2CppInterop.Generator` 生成时出现（`Pass89GenerateMethodXrefCache.cs`），
所以见到它们就说明这个目录是生成器产物，不是手抄的。

## 2. `refs/`：从你自己的正版 APK 解出游戏文件

目标版本：`com.and.games505.Terraria` **1.4.5.8.6**（Unity 2021.3.56f2，arm64-v8a）。

> `libil2cpp.so` 与 `global-metadata.dat` **必须来自同一次构建**，混版本会按错偏移解析。

```bash
adb shell pm path com.and.games505.Terraria
adb shell "cd /data/local/tmp && unzip -o <base.apk> 'lib/arm64-v8a/*' 'classes.dex' 'AndroidManifest.xml' 'assets/bin/Data/*' -d probe"
adb pull /data/local/tmp/probe .
```

把 `probe/lib/arm64-v8a` 与 `probe/assets` 放进 `refs/`，再用 Il2CppDumper 对
`libil2cpp.so` + `global-metadata.dat` 生成 `refs/dump.cs`（查精确签名用）。

细节和目录约定见 [refs/README.md](../refs/README.md)。

## 3. `runtime/`：BepInEx-Android 运行时

上游只发启动器 APK（里面带着 CoreCLR native、`dotnet.zip`、`BepInEx.Android.zip`）：

```powershell
pwsh -File src/csharp/tools/extract-bepinex-android.ps1 -Apk D:\dl\app-release-aligned.apk
pwsh -File src/csharp/tools/prepare-runtime.ps1
```

第一步拆出 `runtime/bepinex-android/{lib,assets}`；
第二步把两个 zip 摊成 `dotnet/`（BCL）与 `bepinex/`（托管栈），并把 ARM64 版
`Il2CppInterop.Runtime/Common` 由 `deploy-runtime.ps1` 部署到 `src/app/src/debug/assets/pylon-interop/`。

## 4. `interop/generated/`：Il2CppInterop 代理程序集

这一目录是 `Assembly-CSharp.dll`、`Il2Cppmscorlib.dll`、`InControl.dll` 等**代理程序集**，
由游戏自己的程序集生成 —— 属于游戏代码的衍生物，**不能进仓库、不能分发**。

生成要求：

- 必须与你部署的 `Il2CppInterop.Runtime` **同一版本**（本机为 `1.5.3`，ARM64 补丁版来自 BepInEx-Android 的 `bepinex/`）。
- 输入是第 2 步解出的游戏文件；输出目录内容原样放进 `interop/generated/`。

两条可行路线（按上游文档为准）：

1. **BepInEx 首启动生成**：让 BepInEx-Android 启动器对着你的游戏跑一次，它会把生成的代理写到
   `BepInEx/interop/`，把该目录整份拷成 `interop/generated/`。
2. **Il2CppInterop 生成器（CLI）**：`external/Il2CppInterop` 里有 `Il2CppInterop.CLI` 与
   `Il2CppInterop.Generator` —— 用 Cpp2IL 对游戏 APK 出 dummy dll，再喂给它生成。

   生成器的参数（取自 `external/Il2CppInterop/Il2CppInterop.CLI/Program.cs`）：

   ```bash
   dotnet run --project external/Il2CppInterop/Il2CppInterop.CLI -- generate \
     --input  <Il2CppDumper 输出>/DummyDll \
     --output interop/generated \
     --game-assembly refs/lib/arm64-v8a/libil2cpp.so   # Android 上 GameAssembly 就是这个 so
   ```

   - `--input` 要的是 **Il2CppDumper 的 `DummyDll` 目录**（不是 `dump.cs`）。
   - 默认会写 `MethodAddressToToken.db` 与 `MethodXrefScanCache.db`；加 `--no-xref-cache` 则不写后者
     （本仓库现有的 `interop/generated/` 是带缓存生成的，两个 db 都在）。

> 生成入口已经内置：`pwsh -File src/csharp/tools/pipeline.ps1 -Stages interop -DummyDir refs\DummyDll`
> （默认全跑时也会自动补这一步；缺 `-DummyDir` 会直接说明要传什么）。
> 如果你的版本与本机一致，最省事的是路线 1；生成后跑 `src/csharp/tools/check-env.ps1` 确认三件齐了：
> `Assembly-CSharp.dll`、`Il2Cppmscorlib.dll`（部署时一并放进 `pylon-interop/`）。

## 5. 部署 → 编译 → 装到手机

一条龙（幂等：子模块 → runtime → interop → 内核 → 托管件 → APK）：

```powershell
pwsh -File src/csharp/tools/pipeline.ps1 -BepInExApk D:\dl\app-release-aligned.apk -DummyDir refs\DummyDll
```

已就绪的阶段会跳过；只重打 APK 用 `-Stages apk`，装到设备加 `-Install`（默认序列号 `3b5f101`）。

分步等价于：

```powershell
pwsh -File src/csharp/tools/check-env.ps1          # 先看还缺什么
pwsh -File src/csharp/tools/deploy-runtime.ps1 # 运行时 native → jniLibs；BCL/框架 → assets；托管三件套
pwsh -File src/core/build.ps1              # 内核 libpylon.so（NDK clang++ 直接编）
gradlew :app:assembleDebug              # 打包（会先编仓库内 Il2CppInterop）
adb install -r -d src\app\build\outputs\apk\debug\app-debug.apk
```

> 当前 debug 形态**默认不把** `refs/` 的游戏资源与原生库打进 APK。启动器从设备上已安装且版本匹配的
> 游戏 `base.apk` 导入关键文件；宿主从 `filesDir/runtime` 加载 `.so`（并把目录追加进 classloader 的
> native 搜索路径），用 `AssetManager.addAssetPath` 挂载所选游戏 APK 的 `assets`。
> 需要“APK 内置 refs、跳过导入”的本地回退时，构建加 `-PpylonStageRefs=true`。
> release 变体把 CoreCLR/BCL/代理也纳入、以及 Android 未来版本对可写目录执行 `.so` 的限制，仍未完成。

真机回归（编托管 → 部署 → 打包 → 安装 → 启动 → 抓日志）：

```powershell
pwsh -File src/csharp/tools/full-test.ps1
```

开发时免重装测试：直接推托管 DLL 到 `files/pylon-managed/` 或把 Mod 放进
`/storage/emulated/0/Android/data/dev.pylon.loader/Mods/<名字>/`（见 `src/csharp/tools/run-test.ps1`）。
运行时的部署判据是「版本号 + 文件数」，**不做字节校验**，所以手推的 DLL 重启后不会被覆盖；
改了 `assets/` 里的东西则要把 [RuntimeDeploy.kt](../src/game/src/main/kotlin/dev/pylon/loader/game/core/RuntimeDeploy.kt) 的 `DEPLOY_VERSION` +1。

## 6. 缺件时的报错对照

| 现象 | 缺的东西 | 补法 |
|---|---|---|
| `找不到 runtime/bepinex-android/...` | `runtime/` | 第 3 步 |
| MSBuild `找不到 Il2Cppmscorlib` / Gradle 报 Harmony 支持层缺引用 | `interop/generated/`、`src/app/src/debug/assets/pylon-interop/` | 第 4 步 + `deploy-runtime.ps1` |
| APK 启动黑屏、logcat 里一条 `I/Unity` 都没有 | 启动器还没导入运行时（或导入不完整） | 打开启动器 → 选择已安装游戏 → 导入运行时；本地回退可 `-PpylonStageRefs=true` |
| `libpylon.so` 不存在 | 内核没编 | `pwsh -File src/core/build.ps1` |
| 设备上还是旧 DLL | `DEPLOY_VERSION` 没 +1 | 见上一节 |
| `UnsatisfiedLinkError: libc++_shared.so` | 运行时 native 没进 APK 的 `jniLibs` | `deploy-runtime.ps1` |

## 7. 两条必须守住的纪律

1. **Hook 只有一套**：Il2CppInterop.RuntimeDetour（仓库内 `src/csharp/il2cppinterop`，已打 ARM64/Disarm 补丁）。
   用 BepInEx 原包那份，`GUIPanel.Draw(..., Nullable<Color>×3)` 这类被挂钩的方法一调用就
   把进程 abort（设置界面一点就闪退）。Gradle 已经把编译这一步接到 `assembleDebug` 前面。
2. **不硬编码游戏偏移**：一切按名字解析，解析失败就让 Mod 停用并写日志（见根目录 README）。

## 8. GitHub Actions：把关键文件产出成 artifact

仓库里有两个 workflow（都在 `.github/workflows/`，只跑 `workflow_dispatch` 或对应路径变更时触发）：

| workflow | 产出 artifact | 内容 | 用在哪 |
|---|---|---|---|
| `build-runtime.yml` → job `bepinex-android` | `BepInEx.Android` | 上游 BepInEx 按钉克隆 + 13 个补丁 + 重建 MonoMod/Il2CppInterop 后打包的 `BepInEx.Android.zip` | `runtime/bepinex-android/assets/` |
| `build-runtime.yml` → job `dotnet-runtime` | `runtime-android` | `dotnet.zip`（微软 10.0.12 运行时的 BCL+PAL）+ `native/*.so` | `runtime/bepinex-android/assets/` 与 `runtime/bepinex-android/lib/` |
| `build-kernel.yml` | `libpylon` | 交叉编译出的 `libpylon.so`（arm64-v8a） | `src/app/src/main/jniLibs/arm64-v8a/` |

这两个 job 的步骤**照抄子模块自己的 CI**（`external/BepInEx-Android/.github/workflows/build-bepinex.yml`
与 `fetch-runtime.yml`），只去掉了 attestation / harden-runner 这些本仓库不需要的环节；
.NET SDK 精确钉在 `10.0.401`（上游 CI 的注释解释了为什么不能用 `10.0.x` 浮版本）。

本地拿到 artifact 之后：

```powershell
# 1) 解压两个 zip 到 runtime/bepinex-android/assets/
# 2) 把 runtime-android 里的 native/*.so 拷到 runtime/bepinex-android/lib/
pwsh -File src/csharp/tools/prepare-runtime.ps1  # 摊成 dotnet/ 与 bepinex/
pwsh -File src/csharp/tools/pipeline.ps1     # 之后一条命令走完
```

**CI 做不了的那一步**：`interop/generated/`（以及依赖它的托管层、APK）需要**你自己的游戏文件**
（`libil2cpp.so` + `global-metadata.dat`）。把游戏二进制塞进 Actions 或公共 artifact 既不合法也不该做，
所以这一步只能在本机按第 4 节生成。生成完 `src/csharp/tools/check-env.ps1` 会全绿，`src/csharp/tools/pipeline.ps1` 就能一路编到 APK。
