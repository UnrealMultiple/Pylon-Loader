# 内容管线：生物群系（Biome）

## 1. 职责

| 游戏时机 | 分派的作者数据 |
|---|---|
| `SceneMetrics.Scan`（每次扫描，玩家侧） | `ModBiome.IsBiomeActive`、`OnEnter`、`OnInBiome`、`OnLeave` |
| `ModBiome.IsSceneEffectActive` | 读本帧标记（场景效果管线问"我激活吗"时用它答） |
| `WorldFile.LoadWorld` | 清标记；退出世界时对还亮着的群落补 `OnLeave` |

**不接**：群落专属音乐、火把/篝火替换物品、图鉴条目与头像、NPC 购物偏好、`DisplayName`、多玩家各算各的（只算本机玩家）。

## 2. 我们的设计

### 2.1 两个文件

`Pipelines/Biome/` 下：`BiomePipeline.cs`（扫描入口 + 边沿状态机 + 三个作者回调）、`BiomeTable.cs`（稠密模板表 + 发号 + 名字查找）。

### 2.2 触发点：`SceneMetrics.Scan` 之后

游戏没有 `Player.UpdateBiomes` 这样的入口（`On.` 里也没有），但每次玩家侧扫描都会走 `SceneMetrics.Scan`。本管线挂在它后面，**扫描一次算一次**，不自己起每帧循环：

* 群落判定读的是方块统计与玩家位置，方块不会在这一帧和下帧之间变出个群落；
* 每帧喊一遍作者写的 `IsBiomeActive`（可能扫方块）比每 N 帧贵得多；
* 游戏自己也是在这个时机更新区域标记的，跟着它走不会出现"标记比方块晚一帧"的错位。

代价写在「这一版没接」：`OnInBiome` 的实际频率是"每次场景扫描一次"，不是每帧。

### 2.3 状态机

每个玩家一组 `bool[]`（长度 = 群落数），存在管线实例上（`bool[][]`，下标是 `whoAmI`，安装期按 `Main.maxPlayers` 一次建好）：

```
now = IsBiomeActive(player)          // 抛异常当 false
if (before == now) { if (now) OnInBiome(player) }
else if (now)      { OnEnter(player); OnInBiome(player) }
else               { OnLeave(player) }
before = now
```

本机玩家走原版扫描（每帧一次）；**别人那一行归归属端**——谁的客户端谁报，服务器转发（见 6.5）。玩家离开时清空他那行标记，免得下次进来带着旧状态。

### 2.4 编号

`ModBiome` 与普通场景效果各有**一套自己的 0 基础编号**，都写在 `ModType.Type` 上但互不混用：一个 `ModBiome` 实例只会进 `BiomeTable`，一个非群落的 `ModSceneEffect` 只会进场景效果表（第 23 条管线）。这样两条管线谁先装都不会抢号，也不需要共享一张表。

### 2.5 `IsSceneEffectActive` 的桥

基类里 `IsSceneEffectActive` 是给普通场景效果用的；`ModBiome` 覆写它，直接读本帧标记（`IsActive(player)`），这样场景效果管线不需要知道"生物群系"这个概念，问一句就能拿到正确结果。

### 2.6 退出世界

读档钩子里：对该玩家还亮着的群落逐个 `OnLeave`，再清空整组标记。用读档钩子而不是"退出按钮"，是因为退出路径不止一条（回主菜单、断线、崩溃恢复），而读档一定发生在新世界开始的时候。

## 3. 取舍理由

* **为什么不自己起每帧循环？** 群落判定是"扫方块"级别的重活，挂在扫描节奏上既省 CPU 又和游戏自己的区域标记对齐；每帧跑一遍纯属浪费。
* **为什么远端玩家不本地复算？** 作者的 `IsBiomeActive` 可能读只在本机有值的 mod 状态（配置、同步过来的玩家数据），两端各算必然对不上，表现是别人的进/出回调在你这台机上乱跳。改成归属端上报 + 服务器转发后，"那个人在不在群落里"只有一个答案。群落的产出（音乐、背景、水、火把）本来就按本机玩家问，网络同步只服务"我看别人的群落"。
* **为什么异常当 false 而不是跳过？** 群落判定失败时"不在这个群落里"是安全的默认：不换音乐、不换背景、不触发进/出；反过来当成 true 会让一个坏群落把整个世界盖成它的配色。
* **为什么 `OnEnter` 那帧也调 `OnInBiome`？** 和 tModLoader 一致——作者常把"进群落的一次性准备"写在 `OnEnter`、"持续表现"写在 `OnInBiome`，进去那一帧就该有表现。这条写进文档免得被当成 bug。

## 4. 失败语义

| 情况 | 游戏侧表现 |
|---|---|
| `IsBiomeActive` 抛异常 | 当 false，记一次；不会把玩家困在群落里 |
| `OnEnter` / `OnLeave` / `OnInBiome` 抛异常 | 记一次，继续处理下个群落 |
| 玩家未激活（死亡/未连接） | 整个扫描跳过，标记保持上一帧的值；网络包到达时玩家已不活跃则只写标记、不派回调 |
| 世界读档 | 先补 `OnLeave` 再清标记；别人的行直接清空 |
| 客户端收到的包 `who` 越界 / 群落号不存在 | 丢弃 |
| 客户端伪造别人的 `who` | 服务器判 `who != from` 直接丢弃，不转发 |
| 服务器在客户端上线前没收到过它的行 | 快照里没有这一行，等它自己第一次进/出时补上 |
| `Refresh` 时作者还没注册完 | 表是空的，扫描走空循环（零开销） |
| 作者群落数量变化（热重载） | 标记数组按 `Count` 重新分配，旧状态丢弃 |

## 5. 扩展方式

要接群落音乐/背景/水：不需要改本管线，在场景效果管线（第 23 条）里把 `ModBiome` 当作普通场景效果参与优先级比较即可——它的 `IsSceneEffectActive` 已经能吃。要接图鉴：在本管线 `Build` 之后给每个群落注册图鉴条目，用 `Type` 做键。

## 6. 与其它管线的边界

* **场景效果管线（23）**：音乐、背景、水、地图背景的"谁赢"归它；本管线只回答"玩家在不在这个群落里"。
* **玩家管线**：`Player` 的字段与生命周期归它；本管线不往 `Player` 上加字段。
* **方块管线**：群落读的是 `SceneMetrics` 已经数好的方块统计，不自己扫 `Main.tile`。
* **安装管线**：`SetStaticDefaults` 与标记数组在 `Static` 阶段建。

### 6.5 别人的群落怎么算（网络同步）

原版只给本机玩家扫场景（`SceneMetrics.Scan` 那条路），别的玩家的群落状态没人生成。本版改成**归属端权威**：

* 客户端每次 `Scan` 后算自己那一行；某个群落进/出时发一条 `[ActionFlag, who, index, enter]`（边沿事件，不是每帧）。
* 服务器收到后先校验 `who == from`（客户端只能报自己），原样转发给其他客户端（不回环给发送者），自己也写进 `_flags`——按群落刷怪的逻辑读到的是同一条真相。
* 其他客户端收到后写标记并派 `OnEnter` / `OnLeave`。
* 新客户端连上时，服务器搭原版「世界数据」消息 7 的车，把手上已亮的行以 `ActionState` 快照发过去；快照**不派回调**（否则一进服就满屏"进入群落"），并且跳过新客户端自己那一行（它自己算）。

**代价（写明不装懂）**：`OnInBiome` 对远端玩家不会每帧派——网络只搬边沿事件；远端玩家的"在里面"持续表现请写在 `OnEnter`/`OnLeave` 的成对逻辑里，或由作者自己按 `IsActive(player)` 轮询。

### 这一版没接

1. **群落音乐 / 背景 / 水 / 地图背景**：归第 23 条场景效果管线；本版群落只产回调与标记，不主动换任何表现。
2. **`OnInBiome` 的每帧语义**：实际频率是"每次场景扫描一次"（见 2.2）。
3. ~~**非本机玩家的群落状态**~~：**已接**——归属端上报 + 服务器转发 + 新客户端快照（见 6.5）。**仍不接**：远端玩家的 `OnInBiome` 每帧语义（只搬进/出边沿）。
4. **群落专属火把 / 篝火物品**（`BiomeTorchItemType` / `BiomeCampfireItemType`）：要拦放置时的物品替换，本版没有。
5. **图鉴条目、`DisplayName`、NPC 购物偏好**：分别归图鉴、本地化与 NPC 管线，本版都没有。
6. **`player.InModBiome(...)` 这类挂在 `Player` 上的桥**：本版提供 `ModBiome.IsActive(player)` 等价查询，不改游戏 `Player` 类型。

### 对作者 API 的影响

| 变更 | 说明 |
|---|---|
| 新增 | `ModBiome.IsActive(Player)`：查本帧标记（`IsSceneEffectActive` 也走它） |
| 语义变更 | `ModBiome.IsSceneEffectActive` 由基类的 `false` 改成读标记；作者不必再自己覆写 |
| 语义明确 | `OnInBiome` 的频率是扫描节奏，不是每帧；`OnEnter` 那帧也会调 `OnInBiome` |
