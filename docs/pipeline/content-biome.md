# 内容管线：生物群系（Biome）

## 1. 职责

| 游戏时机 | 分派的作者数据 |
|---|---|
| `Player.UpdateBiomes`（原版逐玩家更新区旗，orig 之后每玩家） | `ModBiome.IsBiomeActive`、`OnEnter`、`OnInBiome`、`OnLeave` |
| `Player.Update`（发现玩家失活） | 清空该玩家那一行标记，下次进世界不带旧状态 |
| `ModBiome.IsSceneEffectActive` | 读本帧标记（场景效果管线问"我激活吗"时用它答） |
| `WorldFile.LoadWorld` / `WorldGen.SaveAndQuit` | 退出或读档时对还亮着的群落补 `OnLeave`，再清标记 |

**不接**：群落专属火把/篝火替换物品、NPC 购物偏好与心情、tML 风格的本地化键（见 §6「这一版没接」）。群落参与的音乐、背景、水与图鉴条目不在本节——分别经场景效果管线与图鉴钩子接走，边界见 §6。

## 2. 我们的设计

### 2.1 两个文件

`Pipelines/Biome/` 下：`BiomePipeline.cs`（区旗更新入口 + 边沿状态机 + 三个作者回调 + 网络）、`BiomeTable.cs`（稠密模板表 + 发号 + 名字查找）。

### 2.2 触发点：`Player.UpdateBiomes` 之后

原版在这个方法里逐玩家更新 `Zone*` 区旗。本管线挂在它后面（`On.Terraria.Player.UpdateBiomes`），**原版对哪个玩家调一次，就为哪个玩家算一遍**，不自己起每帧循环、也不另挑时机：

* 判定读的是玩家位置、`Zone*` 区旗与作者自己选的数据，区旗刚被原版更新完——判定与原版标记同帧、同序，习惯读区旗的 mod 不会晚一帧；
* 这一时刻读 `SceneMetrics` 方块统计拿到的是上一轮扫描的结果——原版自己更新区旗时面对的也是这个顺序，跟着原版走不引入额外错位；
* 派发域就是原版的调用面：游戏在哪端、对哪些玩家调，mod 群落就在哪端为哪些玩家算——单机是本机玩家，多人是原版调到的每个玩家（服务器端的房主与远端玩家按原版调用范围）。原版跳过的帧，判定与回调随之跳过，标记保持原值。

### 2.3 状态机

每个玩家一组 `bool[]`（长度 = 群落数），存在管线实例上（`bool[][]`，下标是 `whoAmI`，安装期按 `Main.maxPlayers` 一次建好）：

```
now = IsBiomeActive(player)          // 抛异常当 false
if (before == now) { if (now) OnInBiome(player) }
else if (now)      { OnEnter(player); OnInBiome(player) }
else               { OnLeave(player) }
before = now
```

每个玩家一行；单机只有本机玩家那行在动，多人下原版调到谁就更新谁那行，哪一端检测到进/出边沿就由那一端广播（见 6.5）。玩家离开时清空他那行标记，免得下次进来带着旧状态。

### 2.4 编号

`ModBiome` 与普通场景效果各有**一套自己的 0 基础编号**，都写在 `ModType.Type` 上但互不混用：一个 `ModBiome` 实例只会进 `BiomeTable`，一个非群落的 `ModSceneEffect` 只会进场景效果表（第 23 条管线）。这样两条管线谁先装都不会抢号，也不需要共享一张表。

### 2.5 `IsSceneEffectActive` 的桥

基类里 `IsSceneEffectActive` 是给普通场景效果用的；`ModBiome` 覆写它，直接读本帧标记（`IsActive(player)`），这样场景效果管线不需要知道"生物群系"这个概念，问一句就能拿到正确结果。

### 2.6 退出世界

读档钩子里：对该玩家还亮着的群落逐个 `OnLeave`，再清空整组标记。用读档钩子而不是"退出按钮"，是因为退出路径不止一条（回主菜单、断线、崩溃恢复），而读档一定发生在新世界开始的时候。

## 3. 取舍理由

* **为什么不另挑时机，而跟原版 `UpdateBiomes`？** 群落判定的核心输入是区旗，区旗正是原版在这个方法里更新的：挂得太早读到旧区旗，挂到别的时机（比如方块扫描后）反而比原版标记慢半拍。跟着原版更新点走，标记与判定天然同帧；自己再起每帧循环只会重复原版调过的次数。
* **为什么派发域跟原版调用面走？** 原版区旗本来就是逐玩家、在 `UpdateBiomes` 里算的。mod 群落挂同一个入口，作者回调里读到的玩家位置与区旗和本端原版看到的一致，回调时机也不再因实现而异。原版没调到的端拿不到那一行，靠归属端上报的边沿兜底（见 6.5）。
* **为什么异常当 false 而不是跳过？** 群落判定失败时"不在这个群落里"是安全的默认：不换音乐、不换背景、不触发进/出；反过来当成 true 会让一个坏群落把整个世界盖成它的配色。
* **为什么 `OnEnter` 那帧也调 `OnInBiome`？** 和 tModLoader 一致——作者常把"进群落的一次性准备"写在 `OnEnter`、"持续表现"写在 `OnInBiome`，进去那一帧就该有表现。这条写进文档免得被当成 bug。

## 4. 失败语义

| 情况 | 游戏侧表现 |
|---|---|
| `IsBiomeActive` 抛异常 | 当 false，记一次；不会把玩家困在群落里 |
| `OnEnter` / `OnLeave` / `OnInBiome` 抛异常 | 记一次，继续处理下个群落 |
| 原版本次没对该玩家调 `UpdateBiomes` | 本管线跟着跳过，标记保持上一帧的值 |
| 玩家未激活（死亡/未连接） | 原版不调就不判定；网络包到达时玩家已不活跃则只写标记、不派回调 |
| 世界读档 | 先补 `OnLeave` 再清标记；别人的行直接清空 |
| 客户端收到的包 `who` 越界 / 群落号不存在 | 丢弃 |
| 客户端伪造别人的 `who` | 服务器判 `who != from` 直接丢弃，不转发 |
| 服务器在客户端上线前没收到过它的行 | 快照里没有这一行，等它自己第一次进/出时补上 |
| `Refresh` 时作者还没注册完 | 表是空的，入口走空循环（零开销） |
| 作者群落数量变化（热重载） | 标记数组按 `Count` 重新分配，旧状态丢弃 |

## 5. 扩展方式

新增群落相关时机：在 `BiomePipeline` 的入口门里加 `On.` 钩子并分派到对应回调。群落参与场景效果与图鉴条目已接：前者经 `IsSceneEffectActive` 桥以普通场景效果身份进第 23 条管线参与优先级比较，后者按 `Type` 建条目（美术、背景与尺寸校验在 `BiomeBestiaryHooks`）。

## 6. 与其它管线的边界

* **场景效果管线（23）**：音乐、背景、水、地图背景的"谁赢"归它；本管线只回答"玩家在不在这个群落里"，群落的 `IsSceneEffectActive` 读标记参战。
* **玩家管线**：`Player` 的字段与生命周期归它；本管线不往 `Player` 上加字段，`InModBiome` 桥走 PlayerTml 扩展读本管线标记。
* **方块管线**：群落判定读的是 `SceneMetrics` 已经数好的方块统计（上一轮扫描的结果），不自己扫 `Main.tile`。
* **安装管线**：`SetStaticDefaults` 与标记数组在 `Static` 阶段建；没有任何 mod 覆写 `IsBiomeActive` 时不挂任何钩子。

### 6.5 多人：行的同步

多人下原版照样对每个玩家调 `UpdateBiomes`，每端都为原版调到的玩家各算各的。行与行之间的同步规则：

* **任何一端**（客户端或服务器）对某玩家那行检测到进/出边沿，就发一条 `[ActionFlag, who, index, enter]`（边沿事件，不是每帧）——客户端自己那行、服务器算出的房主行与本地算出的远端行，走同一条路。
* 服务器收到后先校验 `who == from`（客户端只能报自己），原样转发给其他客户端（不回环给发送者），自己也写进 `_flags`——按群落刷怪的逻辑读到的是同一条真相。
* 其他端收到后写标记并派 `OnEnter` / `OnLeave`；本端也在算的那行，收到的值与本端标记一致时是空操作，随后本端的重算会照常刷回自己判定的值。
* 新客户端连上时，服务器搭原版「世界数据」消息 7 的车，把手上已亮的行以 `ActionState` 快照发过去；快照**不派回调**（否则一进服就满屏"进入群落"），并且跳过新客户端自己那一行（它自己算）。

**代价（写明不装懂）**：`OnInBiome` 只在"原版在这台机上调它的 `UpdateBiomes`"的端上逐帧派；没被调到的端只收进/出边沿，远端玩家的"在里面"持续表现请写在 `OnEnter`/`OnLeave` 的成对逻辑里，或由作者自己按 `IsActive(player)` 轮询。

### 这一版没接

1. **群落专属火把 / 篝火物品**（`BiomeTorchItemType` / `BiomeCampfireItemType`）：要拦放置时的物品替换，本版没有。
2. **NPC 购物偏好与心情/对话本地化键**：归 NPC 管线，本版没有（`NPCHappiness` 只有原版群落按名字建偏好的壳，且不落库）。
3. **tML 风格本地化键与 PrettyPrint 显示名**：`DisplayName` 是字符串、默认类名直显，图鉴键是 `BiomeName.<类名>`；tML 格式语言文件的键对不上。
4. **远端玩家在"原版没调它的端"上的逐帧 `OnInBiome`**：边沿同步只搬进/出（见 6.5 的代价）。

已接的：群落音乐/背景/水/地图背景（经场景效果管线）、图鉴条目与头像（`BiomeBestiaryHooks`）、`player.InModBiome(...)` 桥（PlayerTml 扩展）、多人下每玩家的行同步（6.5）。

### 对作者 API 的影响

| 变更 | 说明 |
|---|---|
| 新增 | `ModBiome.IsActive(Player)`：查本帧标记（`IsSceneEffectActive` 也走它） |
| 语义变更 | `ModBiome.IsSceneEffectActive` 由基类的 `false` 改成读标记；作者不必再自己覆写 |
| 语义明确 | `OnInBiome` 的频率跟原版 `UpdateBiomes` 的调用节奏；`OnEnter` 那帧也会调 `OnInBiome` |
| 语义明确 | 派发域跟原版调用面：原版对哪些玩家调，回调就对哪些玩家派——多人下同一 mod 在服务器与客户端各自的调用面上触发 |
